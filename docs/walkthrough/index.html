The problem

Small-team projects drift when the truth lives in five places.

Chats carry decisions, spreadsheets carry access requests, notes carry meeting context, and leadership updates become archaeology. Tether turns that scattered surface area into one editable, linked, auditable project record.

03

Update churn

Collaboration

Local-first, shared-folder sync.

Each computer keeps its own SQLite database. Mutations become append-only JSONL operations in a shared folder, typically OneDrive or SharePoint. The SQLite database itself is never placed in the synced folder.

Every teammate keeps a private local database. Edits queue offline, converge field by field through one shared folder, and title/body conflicts are surfaced for review.

1

Edit locally

A teammate changes a status. Tether writes it to their own SQLite database and appends a field-level op to a local log. Instant, and offline-safe.

2

Publish a batch

Tether drops an immutable ops/<device>/…jsonl file into the shared folder. Each device writes only its own directory, so there is no file locking and no shared database.

3

Replay on every other machine

Each teammate's Tether reads new batches, skips ops it has seen, and replays the rest. Lamport clocks order edits; concurrent text goes to the Conflicts screen.

The architecture question

Why not just put it in Neon?

A hosted Postgres like Neon is a great fit for a public demo or a fully approved cloud app. For a small team syncing a work project, it quietly adds a database to secure, credentials to manage, and data leaving the boundary, without removing the hard part. Here is the honest comparison.

Shipped in Tether

Shared-folder op-log

OneDrive / SharePoint + local SQLite

✓
Data stays put. Project data never leaves the folder you already trust. Its ACLs, audit, encryption, and retention apply as-is.
✓
Nothing new to approve. No account, no provisioning, no security review of a third-party database. Uses infrastructure you already have.
✓
Works offline by design. Every device is fully usable with no network. Edits queue and flush when the folder returns.
✓
No credentials, no secrets. Tether makes zero network calls of its own. No connection string to leak, rotate, or hard-code.
✓
Inspectable. Sync artifacts are human-readable JSONL; the merge and audit logic runs locally where you can review it.
Cost: $0. Runs on what the team already pays for.
Neon / hosted Postgres

Managed cloud database

External service over the network

!
Data leaves the boundary. Project records move to a third-party host, often the exact thing an employer's review is meant to prevent.
!
New thing to approve. Account, provisioning, access review, backup/retention decisions, and an ongoing operational owner.
!
Offline still needs a cache. A server DB doesn't remove the hard part. You would still build a local cache and merge layer on top.
!
Credentials to manage. Connection strings and secrets to store, rotate, and keep out of source control.
!
Network dependency. Latency, outages, and a live endpoint become part of the day-to-day experience.
Great later, behind the same interface, once it's approved.

Not a dead end. Tether's sync sits behind a transport interface. The op-log and merge rules stay the same, so an approved backend later (Azure SQL, an internal API, or yes, Postgres) is a swap, not a rewrite. We chose the path that ships today without asking anyone's permission, and kept the door open to the one that might need it.

Architecture and safety

Designed for inspectable, offline-safe project data.

Tether makes no network calls of its own. Sync, if enabled, rides on the folder client the users choose. The renderer runs with context isolation, no Node integration, and a typed IPC allowlist.
